All listings must be converted to a common model, regardless of their origin.

## Requirements

### General information

- [ ] Listing title.
- [ ] Description.
- [ ] Price.
- [ ] Built area.
- [ ] Usable area.
- [ ] Plot area.
- [ ] Number of bedrooms.
- [ ] Number of bathrooms.
- [ ] Property type.
- [ ] Condition.
- [ ] Year of construction, when available.

### Additional features

- [ ] Garage.
- [ ] Garden.
- [ ] Swimming pool.
- [ ] Terrace.
- [ ] Balcony.
- [ ] Heating.
- [ ] Elevator.
- [ ] Energy certificate.
- [ ] Land type.
- [ ] Water.
- [ ] Electricity.
- [ ] Sanitation.

### Provenance and listing status

- [ ] Source portal.
- [ ] Original URL.
- [ ] External identifier.
- [ ] Publication date, if known.
- [ ] Date added to House Radar.
- [ ] Date of last check.
- [ ] Listing status: active, disappeared, or unknown.

## Notes

- Fields must accept unknown values. The absence of a datum in the listing does not mean the property lacks that feature.
- It is advisable to distinguish between data declared by the advertiser, calculated data, and inferred data. See [Ubiquitous language](/domain/ubiquitous-language/).
- Acceptance criteria and dependencies: to be defined in the detailed functional specification.
